Porting EmbedKDECheck to this project

EmbedKdeChecker is a port of Oukelmoun et al.'s EmbedKDECheck. This walks through what the paper actually specifies, where the port deliberately diverges from it, and a threshold bug in the self-density anchor that swung the checker from flagging almost everything to flagging almost nothing before landing somewhere real.

Date 2026‑08‑05 Verified real runs against prim57/cleaned transcripts/prim1.txt + prim57/bad notes lib/prim1.txt, real GloVe embeddings — not simulated

What the paper actually does

Modules/old/kdbe_checker.py already credits this same paper/repo as its source. This port follows it more literally.

Oukelmoun, Semmar, de Chalendar, Cormi, Oukelmoun, Vibert & Allard. “Detecting Omissions in LLM-Generated Medical Summaries.” EMNLP 2025, Industry Track, pp. 325–337. Code: github.com/achok7893/EmbedKDECheck_hallucination_detection.

Given an input (report) and an output (summary), EmbedKDECheck embeds every word of both with a lightweight word-level model (the paper's own FTW2V — FastText+Word2Vec, fine-tuned on a 32M-word French medical corpus), reduces dimensionality with PCA, and fits a Kernel Density Estimate on the output's words only. Every input word is then scored against that KDE:

OMscore(word) = min density over the output's own words ÷ KDE density of that word

A high OMscore means a word is less typical of the output than the output's own least-typical word — evidence the source content around it never made it into the summary. The paper's headline number for a whole document is the maximum token-level OMscore across it, with near-max tokens surfaced as the ones responsible for the flagged omission. This is deliberately one direction only (input → output, omission) — hallucination detection is named explicitly as future work (Section 6).

Validated on 1,348 expert-labeled French medical report/summary/label triplets (80/20 split, threshold + PCA components + bandwidth tuned by random search on the validation set). Benchmarked against SelfCheckGPT, ChainPoll, G-Eval and GPTScore — all GPT-based.

Where this port diverges

Five deliberate deviations, each needed to fit this project's CheckerModule interface or its available tooling — not accidents.

DimensionPaperThis port
Embeddings FTW2V — FastText+Word2Vec, fine-tuned on a 32M-word French medical corpus. GloVe glove-wiki-gigaword-100, general English web-crawl. Reused from this project's other port of the same paper (kdbe_checker.py) rather than a new dependency. Known limitation, documented elsewhere in this repo: GloVe's vocabulary doesn't cover clinical shorthand like “LLQ”.
Direction Omission only: input → output. Both directions — hallucination (SOAP → transcript) added alongside omission (transcript → SOAP). This is exactly the extension the paper names as future work.
Output unit A single global document score, plus per-token scores as supporting evidence. A (type, sentence) flag per candidate sentence — the shape every other checker here returns (AlignScoreChecker, FactKBChecker, KdbeChecker). A sentence's score is the max OMscore among its own words, the direct per-sentence analogue of the paper's per-document max.
Self-density anchor Literal “min density over output words,” computed in-sample, over whole medical reports (hundreds of words). Leave-one-out, 10th percentile — needed once reference sets shrank to transcript/SOAP-sentence size (dozens of words). Full story below.
Calibration Threshold, PCA components, and bandwidth tuned by random search on a held-out validation split of 1,348 labeled triplets. Still uncalibrated — the same starting point every checker in this repo has carried before its own labeled threshold sweep (see kdbe_checker.py, AlignScoreChecker, FactKBChecker's own THRESHOLD comments).

Debugging the self-density anchor

The paper's formula divides by a word's KDE density — so whatever the numerator (the anchor) is set to determines almost everything about how trigger-happy the checker is. Three attempts, same file (prim1.txt: 15 SOAP sentences, 113 transcript sentences, 128 candidates total) each time.

Attempt 1 — literal paper formulain-sample min, threshold = 1.0
112 / 128candidates flagged (87.5%)

The anchor was the reference's own words scored under a KDE that includes each word's own kernel contribution — which inflates its density (the point boosts its own score). An unseen candidate word never gets that same self-boost, so comparing its density against that inflated in-sample floor is structurally unfair: almost any candidate word, including well-matched ones, scores below it. Combined with max-aggregation, one such word sinks the whole sentence — “if it's not one-for-one it fails.”

Attempt 2 — leave-one-out minovercorrected
0 / 128candidates flagged (0%)

Scoring each reference word under a KDE fit on every other reference word removes the self-inflation — but anchoring on the strict minimum is still fragile once the reference set is small. A transcript/SOAP sentence is dozens of words, not the paper's whole medical report (hundreds), so the anchor ends up dominated by whichever single reference word happens to be the most unusual one, in or out of sample.

Attempt 3 — leave-one-out, 10th percentileshipped
64 / 128candidates flagged (50%)

Same leave-one-out fix, anchored to the 10th percentile of those scores instead of the strict min — keeps the paper's “near the floor” intent without being hostage to one outlier word. The omission-heavy skew is expected, not a bug: the transcript is dozens of conversational turns against a short, condensed SOAP note, so most turns genuinely won't resemble the note's clinical register — the same recall/precision imbalance this project's other checkers hit before their own threshold sweeps (see evaluate_fixes_report.html).

Still uncalibrated: both THRESHOLD = 1.0 and SELF_DENSITY_PERCENTILE = 10 are principled starting points, not swept values — there's no labeled threshold sweep behind them yet, the same state every other checker here started in before its own.
