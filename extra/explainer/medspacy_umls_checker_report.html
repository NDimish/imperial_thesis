MedspacyUmlsChecker

A deterministic SOAP-note QA checker: UMLS concept extraction, medspaCy ConText assertion tagging, then three independent judgments — including status flip, a check no other module in this project makes.

Why a third judgment

The project's existing concept checker matches transcript and SOAP-note entities by (CUI, is_negated) as a single combined key. That's enough to catch a concept that's fully missing or fully invented — but when a concept flips polarity between documents, it can only ever report that as one hallucination plus one omission, never as the one fact that's actually true: the same concept, asserted with the opposite meaning.

status_flip matches by CUI first, then compares assertion state separately — so "patient denies diabetes" in the transcript against a SOAP note that asserts diabetes affirmed is reported as exactly one thing: a flipped concept, not two unrelated errors.

Pipeline

Three steps, run once per document, then compared.

STEP 1 — EXTRACTION

UMLS concept spans

The project's shared QuickUMLS matcher finds every disease, finding, procedure, and drug mention (T047/T121/T195/T200/…), independent of any hand-typed vocabulary.

matches = self._matcher.match(
    text, best_match=True,
    ignore_syntax=False,
)
# (start, end, cui, term) per hit
→
STEP 2 — CONTEXT

ConText assertion tagging

Spans are injected as spaCy entities and run through medspaCy's medspacy_context pipe, which sets is_negated / is_uncertain / is_family per entity.

doc.ents = spacy.util.filter_spans(
    candidate_ents
)
nlp.get_pipe(
  "medspacy_context"
)(doc)
→
STEP 3 — JUDGING

Three comparisons

Transcript and SOAP-note concept sets are compared by CUI to raise omission, hallucination, and status_flip — independently, never double-counted.

state = (
  is_negated,
  is_uncertain,
  is_family,
)

Known noise: most flagged omissions are conversational filler that happens to fuzzy-match a UMLS term ("confirm", "maybe", "sort", "your age") — the same class of false positive already documented and partly denylisted in the project's earlier concept checker. Precision on the omission/hallucination axis would benefit from the same iterative denylist tuning; the status_flip judgment is largely unaffected since it only fires on concepts both sides already agree are real.
Deterministic throughout — QuickUMLS + medspaCy ConText only, no LLM call, no sampling. Same two inputs always produce the same concept sets and the same errors. Modules/medspacy_umls_checker.py · class MedspacyUmlsChecker(CheckerModule) · not yet wired into main.py's load_checker_modules()
