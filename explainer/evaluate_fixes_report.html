Evaluation harness · bug fixes

Six fixes to how checker predictions get scored

The precision/recall numbers from Modules/evaluate.py and the omission scores from Medical condensor/evaluate.py had real bugs sitting underneath them. Here’s what was wrong and what changed — including one fix attempt that failed and was replaced with a working one.

Date 2026‑07‑30 Verified real labels, real transcripts, real model runs — not estimates
Biggest fix

Omission predictions couldn’t match omission labels — at all

A checker module’s omission prediction is the literal transcript sentence it flagged. An omission label’s detail text is the literal ground-truth-note sentence that went missing. Those are two different registers describing the same fact — clinical shorthand vs. spoken dialogue — and plain substring matching almost never bridges them. Every checker’s omission recall was structurally close to zero, independent of how good the underlying model actually was.

Attempt 1 — GloVe word vectorsrejected after testing

relevant0.548“so in my lower abdomen… just to one side.”
relevant0.454“on the left side.”
unrelated0.571“loss of appetite… hold down fluids” — scores higher than 3 of 4 real matches

Root cause: “LLQ” — the single most distinguishing word in the label — isn’t in GloVe’s general web-crawl vocabulary, so it’s silently dropped. No threshold can fix this; it’s the wrong tool.

sentence-transformers/all-MiniLM-L6-v2, loaded via plain transformers (already a dependency — no new package). Threshold set to 0.15. Clean separation: every unrelated sentence now scores below the relevant ones, reversing what GloVe produced.

✓ End-to-end test on real prim1.txt labels: 3 predicted errors in, all 3 correctly matched — tp=3, fp=0, fn=0. One of the three (“There’s no one with the same symptoms.” against label “No other unwell contacts.”) has zero word overlap and could only have matched through the new embedding path.

Five smaller fixes

A hallucination-style signal was labeled “omission”

omission_soap_to_transcript→groundedness_soap_in_transcript

kdbe_check.py’s own docstring already said this direction measures whether SOAP content is grounded in the transcript — a hallucination-adjacent signal, not an omission one. Every log line, JSON field, and plot label still called it “omission,” which would mislead anyone reading the results without re-deriving the math. Renamed consistently across kdbe_check.py, Medical condensor/evaluate.py, and NLP_Main.py’s plot.

Positive or negative — which way is “better”?

Lower raw KDE scores are the stronger signal, so diff = condensed − original being positive means condensing improved things — the opposite of how “the number went up” usually reads. Nothing said this anywhere. Added it to the class docstring, a printed note in results(), and the plot panel titles directly (“+improved”).

Dropped records vanished with no trace

If a condenser over-filters and the condensed text drops below 6 recognized words, check_omissions() returns None for that record — and it silently fell out of every average. _log_average() now reports how many records were dropped alongside each average, so an over-aggressive condenser’s data loss is visible instead of hidden inside a smaller denominator.

Two KDE files, two different fitting strategies — on purpose

Modules/kdbe_checker.py (per-sentence) fits scaler/PCA on the reference document only, so it has one stable space to test many candidate sentences against. Medical condensor/kdbe_check.py (whole-document) fits on the concatenation of both texts, matching the original Embed2KDE repo it was ported from. Rather than force these identical and lose either rationale, both files now cross-reference each other with a comment explaining the difference is deliberate — scores from the two aren’t on a directly comparable scale.

One missing null-guard

results() summed elapsed across all records without filtering None values, unlike every other averaged field. Not live-broken today — every condenser always returns a real elapsed time — but inconsistent, and would crash the moment that stopped being true. Brought in line with the rest.

All comparisons above were run directly against this project’s real data: the label file at prim57/bad notes labels lib/prim1.txt and its source transcript. The GloVe and MiniLM similarity scores are actual model output, not illustrative numbers, and the tp/fp/fn result is a real call to Evaluate.compare() after the fix.
